# 安装与开始

## 识别当前环境

1. 核对是否为 macOS。非 macOS 可以整理内容，但不能安装和运行原生 App。
2. 先查用户指定位置、`/Applications/Remeet.app`、`~/Applications/Remeet.app`；已有旧版时也检查对应的 `NotchRecall.app`。开发仓库中的 `build/Remeet.app` 仅在用户正在使用该仓库或明确提供路径时作为本地测试包。
3. 读取 App 的 `Contents/Info.plist`，确认显示名、版本、可执行文件和兼容 Bundle ID。当前兼容标识为 `local.NotchRecall`；可执行文件名从 `CFBundleExecutable` 读取。
4. 检查是否已有实例运行。不要再启动另一份 App，不自动退出或替换用户正在编辑的实例。

## 安装或升级

- 以项目已配置的仓库地址或用户提供并核实的官方 Release 为下载来源。不要仅凭名称搜索后安装同名第三方软件，也不猜 GitHub 账号、下载地址和版本。
- 当前仓库尚未绑定公开 Release。没有真实下载入口时，说明这一点；用户提供了本地测试包可协助使用，不能宣称已通过正式签名、公证或另一台 Mac 验收。
- 当前分发为未经过 Developer ID 签名和 Apple 公证的 ZIP。核对支持系统及架构，下载 Release 的 App ZIP 附件；自动生成的 Source code ZIP 不是安装包。解压后将 Remeet.app 拖入 Applications，再打开，无需要求普通用户构建源码。
- 替换前先保存编辑器草稿并正常退出。目标存在时保留可恢复的旧版本，不覆盖正在运行的包。首次打开若因未知开发者或未公证被拦截，说明用户可在确认来源后，通过“系统设置 → 隐私与安全性 → 仍要打开”单独允许。遵循当前工具要求的用户确认；不关闭整个 Gatekeeper 或移除隔离属性。损坏、恶意软件提示或受管设备限制须单独核查，不当作普通未公证提示。
- 优先使用当前环境的应用控制工具启动，核对进程或菜单栏入口；设备锁定时等待解锁，不把发起启动等同于已运行。

## 第一次回顾

打开菜单栏“我的内容” → 添加内容 → “保存并生效” → “预览这条”。预览展示编辑器选中的已保存笔记，不改变随机条目或调度。菜单“立即回顾”展示当前选中项，“换一条回顾”切换后展示，均不改变定时计划。只有明确需要带入笔记时才进入内容导入流程。

现有用户数据和偏好沿用兼容目录/Bundle ID；升级不应手工迁移数据。新用户自带内容标注为示例，不冒充真实笔记。
